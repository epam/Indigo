How this codebase models chemistry — not chemistry in general. Where the two disagree, the codebase
wins and the disagreement is worth a comment.

## Structures

**Molecule** (`core/indigo-core/molecule/molecule.h`) — a graph of atoms and bonds with explicit
per-atom state: element, charge, isotope, radical, explicit and implicit hydrogen counts, valence.
Derives from `BaseMolecule`, which owns everything shared with queries: the graph, coordinates,
S-groups, R-groups, highlighting, and the copy/merge machinery.

**QueryMolecule** — the same graph carrying *predicates* instead of concrete values: "any halogen",
"aromatic bond", "ring bond count ≥ 2". A great many bugs come from code that assumes a
`BaseMolecule` is a concrete `Molecule`; check `isQueryMolecule()` before reading concrete state.

**Reaction / QueryReaction / PathwayReaction** (`core/indigo-core/reaction/`) — ordered collections
of molecules split into reactants, products and catalysts, plus atom-to-atom mapping (AAM).

**Sub-structures inside a molecule**

- **S-group** — a labelled set of atoms: superatom (abbreviation), SRU (polymer repeat unit),
  multiple group, data group. Survives most edits and must be remapped on every atom removal.
- **R-group** — a numbered substitution site plus its alternative fragments; the basis of Markush
  structures and of R-group deconvolution.
- **Stereocentre / cis-trans bond / allene** — stereo configuration is *side data* keyed by atom or
  bond index, held by companion classes (`MoleculeStereocenters`, `MoleculeCisTrans`), not by the
  atom itself. This is why invariant A5 exists.

## Cross-cutting concepts

**Valence and implicit hydrogens.** Implicit H count is derived from element, charge, radical and
bond orders under a valence model; the model is configurable (the BIOVIA 2009 vs 2017 rules), so the
same structure legitimately yields different implicit-H counts under different options. Never assume
a single correct answer without knowing which model is active.

**Aromaticity.** Indigo distinguishes an aromatic *representation* (bonds typed aromatic) from an
aromatic *perception*. `dearomatize` reconstructs alternating single/double bonds; a computation that
depends on bond orders must state which of the two forms it expects.

**Canonicalisation.** Canonical SMILES (`canonical_smiles_saver.h`) and the canonical ranking behind
it are the identity function for structures — exact search, duplicate detection and Bingo indexing
all rest on it. A change to canonical ranking invalidates stored indices downstream.

**Coordinates and layout.** 2D coordinates are either read from the file or generated by
`core/indigo-core/layout/`. Layout is heuristic and *not* reproducible bit-for-bit across platforms
(invariant A9).

## Formats

Text formats — SMILES, SMARTS, SMILES extensions, InChI (via the third-party library), CML, KET —
and binary/record formats — MOL/SDF V2000 and V3000, RXN, RDF, CDX/CDXML, CMF (Indigo's own compact
form used by Bingo). Each has a `*_loader.h` / `*_saver.h` pair under `core/indigo-core/molecule/`
or `reaction/`. KET is the interchange format shared with Ketcher.

The authoritative descriptions of MOL/SDF/RXN semantics are the BIOVIA CTfile specifications; where
the code deviates deliberately, the deviation belongs in a comment with the section number.
